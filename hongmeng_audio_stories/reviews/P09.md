## 交错可达性与状态保护

- 第 N 轮已执行 Pause 后再进入 Process；HandleMsg 只摘取一次当前批次，因此 Process 内外部线程成功发布的 Start 不会插入本轮已摘批。Gain 随后发布 F，成功发布次序 Start、F 形成头插链 F→Start。
- 第 N+1 轮摘下后反向调用，先 Start 后 F。Start 先设输入 RUNNING、调用 ConnectInputSession、设置淡入并复位 fadeOutState；F 真正执行时回读 RUNNING，直接返回，保护当前通路。
- 同批 Pause→Start 的反例直接可见；SetFadeState(OPERATION_STARTED) 复位 NO_FADEOUT，此时后续 Process 不必产生本例旧 F。页面没有把条件交错推广为任意 Pause/Start 必然出现的事件。
- 去掉执行时 RUNNING 守卫的反事实成立：对于此时 RUNNING 输入，旧收尾会选择 PAUSED、按存在性暂停会话音效、Disconnect、更新状态并回调。检查放在发布时只能看到旧时刻，不能替代闭包内部当前条件检查。
- 讲稿准确限定守卫并非暂停代次令牌；不能用它证明另一次 Pause 后的所有旧完成事件都已被识别。公共 Drain 的 I_STATUS_DRAINING 守卫也正确区分为服务层例子，未当作同一引擎状态机或自研专属机制。
